# 👤 Profile -- who is operating this package

Never committed. This folder is why `foundations/` can stay standalone: the discipline describes how the work is done by anyone, and everything that is true of **one person** lives here instead.

The test is the same one the areas use, turned around. If a statement is only justified by *this* engineer's preference, history or circumstance, it belongs here. If it would hold for anyone doing this work, it belongs in `foundations/`. A preference that leaked into doctrine would make the doctrine unportable, which is the failure this folder prevents.

| File | Holds |
|---|---|
| [`preferences.md`](preferences.md) | Choices the discipline deliberately leaves open, and which way this engineer has decided them |
| [`growth.md`](growth.md) | Where this engineer is going, and what to teach next |
| [`linear_updates.md`](linear_updates.md) | How this engineer writes a tracker update |
| [`harness_manifest.md`](harness_manifest.md) | What is actually installed and running on this bench, keyed by capability so it ports. Template and method: [`templates/harness_manifest.md`](../templates/harness_manifest.md); same-harness reproduction: [`templates/claude_home/`](../templates/claude_home/README.md) |

Coaching reads this folder. [`foundations/Coaching/`](../foundations/Coaching/README.md) holds the method -- how to run a session, how to judge mastery from evidence -- and names no person. Who is being coached, at what level, and what their next exercise is, is here.
